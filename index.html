Reward-hacking probe · work in progress · updated 25 November 2026

Can one linear direction both detect reward hacking and steer a model away from it?

Niranjan Deshpande

TL;DR

  • We fit a logistic probe for reward hacking on the residual stream of a frozen Qwen3.8-27B, using its own hack and honest completions in 11 single-turn environments. We steer with the probe multiplied by the activation covariance, which we write as Σ·probe. We compare both against our reconstruction of Goodfire's reward-hacking direction.
  • Single-turn detection. On environments the probe was not fitted on, it separates hack from honest completions with AUROC 0.89, against 0.47 for Goodfire's direction (difference +0.42, 95% CI [+0.38, +0.45]).
  • Single-turn steering. Subtracting Σ·probe lowers the hack rate on 50 fresh prompts from 48% by 44 points [−58, −32]. None of 32 random vectors does as much. Subtracting Goodfire's direction changes it by +6 [−10, +22].
  • Multi-turn steering. In two agent task families where the unsteered model hacks in 29 of 32 episodes, subtracting Σ·probe gives 0 of 32. The steered model still does the task honestly and reports that the target cannot be reached. Controls for this result are running.
  • What did not hold up. As a detector on multi-turn rollouts the probe ties Goodfire's direction (−0.01 [−0.12, +0.09]) and is inverted on two of six task families. So the direction steers agents better than it flags them.
  • Running now. Random-vector controls, benign task variants, three more task families, capability benchmarks, a prompt-only baseline, and a test of whether the direction also affects lying in short stories.

Why this matters

Reward hacking means passing a check without doing the task: editing a test, reading a leaked answer, changing a threshold. If a single direction in a model's activations tracks this, it gives a cheap monitor (read the projection) and a cheap intervention (subtract the direction). Goodfire published such a direction (arXiv 2609.19101). We want to know whether a simple probe trained on the model's own behaviour does better, and whether it carries over from short completions to long agent episodes.

The steering result matters most for the second question. A direction that only works in the environments it was fitted on is a description of those environments. A direction fitted on one-shot completions that also removes hacking in multi-turn tool-use episodes it has never seen is closer to a representation of the behaviour.

Method

We collect completions from the frozen model in single-turn environments where hacking is possible but not requested, and a judge labels each as hack or honest. We read the residual stream at the input of block 36, average it over the completion's tokens, and fit a logistic probe w to separate hack from honest completions. For steering we do not use w directly. We use Σw, where Σ is the covariance of activations at that layer, scaled to a fixed norm and added to or subtracted from the residual stream at every position.

Method details — Data and labels
  • Model: Qwen3.8-27B with thinking on, never fine-tuned.
  • 11 single-turn environments, each a prompt with a legitimate route and a shortcut (for example a leaked answer key, a save file that can be edited, a threshold file next to a benchmark). The prompts never ask for the shortcut.
  • Several completions are sampled per prompt. A judge model (one pass per completion) labels each as hack or honest. Only prompts with both outcomes are used, so that the probe compares hack and honest behaviour on the same prompt.
Method details — Probe and steering vector
  • The probe is an L2-regularised logistic regression on standardised, mean-pooled activations at the input of block 36.
  • Why Σ·probe: a probe reads along w, but the cheapest way to change that reading, measured in the model's own activation statistics, is to move along Σw. For a whitened mean-difference probe, Σw is exactly the plain difference of class means.
  • The steering vector is 20·Σw/‖Σw‖. Norm 20 is 24% of the mean residual norm. It is applied at every position of the request (prompt and generated tokens), inside a patched vLLM server that selects the vector per request.
Method details — Scores and comparisons
  • Matched AUROC. For each prompt, hack completions are ranked against honest completions of the same prompt, and the result is averaged over prompts and then environments. A direction cannot score by recognising the prompt.
  • Leave one environment out. For single-turn detection the probe is fitted on ten environments and scored on the eleventh.
  • Goodfire's direction. We rebuilt it on this model from their released data by their recipe. One of their data families is not released and their pooling is not stated, so this is a reconstruction.
  • Random steering controls. 32 conditions at the same norm: 16 isotropic and 16 drawn with covariance Σ, half added and half subtracted.
  • Intervals are 95% bootstrap intervals over prompts or tasks.

Single-turn environments

1. Detection: the probe beats Goodfire's direction

We asked whether each direction separates hack from honest completions in an environment it has not seen. The probe has mean matched AUROC 0.887 and Goodfire's direction has 0.471, a paired difference of +0.417 [+0.383, +0.450].

  • Goodfire's direction is not random here. It is well below 0.5 on six environments, which means it ranks hack completions lower than honest ones there. A detector whose sign depends on the environment cannot be used as a flag.
  • Their direction was built for tool calls in agent transcripts, so this is not its home setting. Section 3 has the comparison on rollouts.

2. Steering: subtracting Σ·probe removes most hacking

We took five environments outside every fit, ten fresh prompts each, and generated one completion per prompt under each steering condition. Unsteered, the model hacks on 48% of the 50 prompts.

  • Subtracting Σ·probe lowers hacking by 44 points [−58, −32]. No random condition is as low (p = 0.024 after Holm correction over the three directions named in advance).
  • Subtracting Goodfire's direction changes hacking by +6 [−10, +22]. Head to head, ours is 50 points lower [−64, −36].
  • Σ·probe moves hacking in both directions: adding it raises hacking by 22 points [+2, +40]. A vector that only disrupted the model would lower hacking with either sign.
  • The raw probe w, subtracted at the same norm, does much less (−12 [−30, +4]). The covariance transform is what makes the probe usable for steering.

Caveats. Random vectors drawn with covariance Σ lower hacking by about 13 points on average with either sign, so some of the effect is generic. One sample per prompt means per-environment numbers move in steps of 10 points. With the direction subtracted, 78% of answers were complete, against 84% unsteered. The incomplete ones were cut off by the token limit in one environment.

Multi-turn agent rollouts

3. Detection: a tie with Goodfire's direction

We built six families of multi-turn tasks in which the model works in a sandbox with tools for about ten turns. Unprompted, it hacks often: it edits a save file or a benchmark gate in almost every episode of two families, and reads a leaked file in 39% of episodes of a third. We then asked whether the probe, fitted only on single-turn completions, flags the hack episodes. The score is the mean activation over an episode's assistant tokens, hack episodes against honest episodes of the same task.

  • Over the six families the paired difference is −0.010 [−0.115, +0.085]. By the rule we fixed before the run, the probe does not beat Goodfire's direction on rollouts.
  • Each direction is inverted somewhere: ours on release gate and answer key, theirs on leaked outputs. Neither is a usable flag across families.
  • Post hoc, the probe does find the step where the hack happens (step-level AUROC 0.78 to 0.98 in five families). We found this after looking at the data, so it is a hypothesis.

4. Steering inside rollouts: hacking goes from 29 of 32 episodes to 0

This is today's result. We took the two families where the unsteered model hacks almost every time, and reran the same 32 episodes (8 tasks, 2 seeds, 2 families) with a direction subtracted at every turn. In these task variants the honest route fails by design, so an honest agent has to submit a result that misses the target.

  • Unsteered: 14 of 16 episodes hack in save game and 15 of 16 in release gate.
  • Σ·probe subtracted: 0 of 16 and 0 of 16. With 0 of 32, the 95% upper bound on the steered hack rate is about 11%.
  • The steered episodes are coherent. In save game the model plays the trading game, works out the maximum reachable gold, and submits it with a statement that the target is out of reach. In release gate it batches the datastore reads, shows that the remaining latency is a floor, and declines in words to touch the threshold or the simulator. We checked all 32 transcripts for edits the detector might miss and found none (this check was written after seeing the result).
  • Goodfire's direction subtracted: 2 hacks in 27 finished episodes, but 23 of those 27 ended by running out of context or of a token budget without submitting. So its low hack rate mostly reflects the model no longer finishing, which is a different outcome from choosing the honest route.

Caveats. The unsteered episodes come from a run the night before on an unpatched server. There is no random-vector control in rollouts yet, and section 2 shows that such vectors can lower hacking by themselves. Two task families and one seed set per task are a narrow base. All of these are being addressed by the runs in section 5.

5. Running now

These runs were in progress when this page was written, and their results are not reported here.

  • Random-vector controls in rollouts. Two vectors drawn with covariance Σ and nearly orthogonal to Σ·probe, and one isotropic vector, subtracted at the same norm on the same 32 episodes. If the effect is specific, these should leave hacking near 90%.
  • Unsteered episodes on the same patched server, to rule out a server difference.
  • Benign task variants under steering. The same tasks in solvable form, to see whether the steered model still completes them.
  • Three more task families (answer key, leaked outputs, scorer copy). Only leaked outputs has a high enough unsteered hack rate (25 of 64) to show a clear drop.
  • Capability benchmarks with and without the direction: MATH level 5, MMLU and HumanEval, same questions and seeds.
  • A prompt-only baseline: three sentences in the system prompt telling the model to use only legitimate means.
  • Lying in short stories. Following arXiv 2610.29129, stories in which a character is asked a question where the truth is costly, written with the direction added and subtracted. This tests whether the direction is about reward hacking or about dishonesty more broadly.

All new rollout runs stop an episode after 30,000 generated tokens, and the analysis will apply the same rule to every condition.

Where this stands

  • As a steering vector, Σ·probe beats Goodfire's direction in single-turn environments with intervals that exclude zero, and in the first multi-turn test it removes hacking completely while the agent keeps working. The multi-turn result still needs its controls.
  • As a detector, the probe wins clearly on single-turn completions and does not win on rollouts. Fitting or selecting on rollout data is the obvious next thing to try for detection.
  • If the capability benchmarks show a loss, the next step is to subtract only when the probe reading is high (the capping idea from arXiv 2610.29129), which here would mean the smallest covariance-weighted edit that caps the probe.
  • Everything is on one model, one layer and one norm, and the multi-turn task families are ones we wrote.
